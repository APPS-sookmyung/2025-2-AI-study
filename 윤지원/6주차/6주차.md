## 1. 연구 배경 및 목표

본 연구는 복잡한 다중 홉(Multi-hop) 질문-답변(QA) 시스템에서 발생하는 두 가지 핵심 문제를 해결하는 것을 목표로 합니다.

1.  **속도와 정확성의 트레이드오프 (Speed vs. Accuracy):** 모든 질문을 복잡한 추론 에이전트에게 맡기면 단순한 질문 처리 시 불필요한 지연 시간이 발생합니다.
2.  **환각 및 신뢰도 저하 (Hallucination):** 다중 홉 추론 과정에서 에이전트가 사실에 근거하지 않거나 잘못된 답변을 생성할 위험이 있습니다.

## 2. 핵심 아이디어: 두 가지 연구의 통합

본 아키텍처는 위 문제들을 해결하기 위해 이전에 연구된 두 가지 핵심 아이디어를 계층적(Hierarchical) 구조로 통합합니다.

1.  **[연구 1] 지연 시간 예산 컨트롤러 (Latency Budget Controller):**
    * 질문의 복잡도를 '단순(Simple)'과 '복잡(Complex)'으로 분류합니다.
    * 분류 결과에 따라 쿼리를 신속 처리(경량 RAG) 또는 정밀 처리(중량 에이전트) 경로로 동적으로 라우팅하여 속도와 정확성을 모두 최적화합니다.

2.  **[연구 2] 자가 교정 LangGraph 에이전트 (Self-Correcting LangGraph Agent):**
    * LangGraph의 순환적(Cyclic) 및 상태 저장(Stateful) 특성을 활용합니다.
    * 에이전트가 스스로 답변을 생성하고(Generate), 생성된 답변을 비판적으로 검토(Reflect)하며, 오류 발견 시 피드백과 함께 재작성(Retry)하는 자가 교정 루프를 구현합니다.

## 3. 통합 아키텍처 (Hierarchical_RAG_V5)

제안하는 최종 아키텍처는 `매니저 그래프`와 `워커 그래프`라는 두 개의 LangGraph 계층으로 구성됩니다.

### 3.1. Manager Graph (매니저 그래프): 지연 시간 예산 컨트롤러

최상위 그래프이며 전체 작업의 계획 및 라우팅을 담당합니다. (연구 1의 'Latency Budget Controller' 역할 수행)

* **Dynamic Planner (동적 계획가):**
    * 사용자의 원본 질문을 분석하여 해결에 필요한 하위 질문(Sub-query)들로 분해하고 작업 계획을 수립합니다.
* **Executor (작업 실행기):**
    * **핵심 기능 (Latency Budget Control):** `Sub-query Classifier`를 통해 하위 질문의 복잡도를 '단순' 또는 '복잡'으로 분류합니다.
    * **Routing (단순):** '단순' 질문은 경량 RAG 체인(`manager_simple_rag_invoke`)을 통해 신속하게 답변을 생성합니다.
    * **Routing (복잡):** '복잡' 질문은 정밀한 추론과 검증을 위해 아래의 `워커 그래프`로 작업을 위임합니다.
* **Merger (답변 종합기):**
    * 모든 하위 질문과 검증된 답변 조각들을 취합하여 원본 질문에 대한 최종적이고 논리적인 답변을 생성합니다.

### 3.2. Worker Graph (워커 그래프): 자가 교정 루프

'복잡'으로 분류된 단일 하위 질문을 받아 정밀하게 처리하고 스스로 검증합니다. (연구 2의 'Self-Correction Agent' 역할 수행)

* **Retrieve (검색):** 하위 질문에 대해 `검색 서브시스템`을 호출하여 사실적 근거(Context)를 확보합니다.
* **Generate (생성):** 확보된 근거만을 사용하여 답변 초안을 생성합니다.
* **Reflect (검증):** 생성된 답변이 근거 문서에 충실한지(Faithfulness), 환각은 없는지 엄격하게 검증합니다.
* **Self-Correction Loop (자가 교정):**
    * `Reflect` 노드가 답변에 결함('retry_with_feedback')을 발견하면, 수정 피드백과 함께 `Generate` 노드로 작업을 되돌려보냅니다.
    * 이 순환 과정을 통해 답변의 신뢰도를 최대 2회까지 반복적으로 향상시킵니다.

### 3.3. Shared Subsystem (공유 서브시스템): 하이브리드 검색

모든 에이전트(매니저/워커)가 공유하는 고성능 검색 모듈입니다.

1.  **Hybrid Search (BM25 + FAISS):** 키워드 기반 검색과 의미 기반 벡터 검색을 결합하여 초기 후보 문서를 추출합니다.
2.  **Re-ranker (Cross-Encoder):** 추출된 후보 문서들을 질문과 직접 비교하여 가장 관련성 높은 최종 문서를 선별, 에이전트에게 제공합니다.

## 4. 전체 흐름 요약

1.  사용자 질문이 **Manager Graph**의 `Dynamic Planner`에 전달됩니다.
2.  질문이 하위 질문들로 분해되고, `Executor`가 각 하위 질문을 '단순/복잡'으로 분류합니다.
3.  **단순 질문**은 `Executor`가 즉시 처리합니다.
4.  **복잡 질문**은 **Worker Graph**로 위임되어, `Generate` -> `Reflect`의 **자가 교정 루프**를 거쳐 검증된 답변이 생성됩니다.
5.  모든 하위 질문 처리가 완료되면, `Merger`가 검증된 답변 조각들을 종합하여 최종 답변을 사용자에게 반환합니다.
